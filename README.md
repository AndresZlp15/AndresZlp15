## 🏗️ Arquitectura & Principios de Desarrollo

<details>
<summary><b>🧱 Clean Code & Patrones de Diseño</b> — click para expandir</summary>
<br>

> Aplico principios sólidos que garantizan código mantenible, extensible y fácil de escalar.

| Principio | Descripción |
|-----------|-------------|
| **SOLID** | Diseño orientado a objetos con responsabilidad única, abierto/cerrado, sustitución Liskov, segregación de interfaces e inversión de dependencias |
| **DRY / KISS** | Evito duplicación de lógica y priorizo soluciones simples sobre sobre-ingeniería |
| **GoF Patterns** | Factory · Singleton · Builder · Observer · Facade · Decorator · Strategy · Command |
| **Clean Architecture** | Separación en capas: Dominio → Aplicación → Infraestructura → Presentación |

</details>

<details>
<summary><b>⚙️ Backend & Microservicios</b> — click para expandir</summary>
<br>

> Arquitecturas distribuidas con alta cohesión, bajo acoplamiento y resiliencia ante fallos.

| Patrón / Técnica | Tecnologías |
|------------------|-------------|
| **Microservicios** | Servicios independientes con contratos API bien definidos |
| **Event-Driven** | Comunicación asíncrona entre servicios con colas y webhooks |
| **APIs RESTful** | Versionado, paginación, rate-limiting y documentación Postman |
| **WebSockets** | Comunicación bidireccional en tiempo real |

<br>

> Implemento capas de seguridad robustas desde el diseño inicial.

| Mecanismo | Descripción |
|-----------|-------------|
| **JWT / OAuth2** | Tokens firmados con expiración y refresh seguro |
| **Auth Multi-Rol** | Control de acceso granular por permisos y roles |

| **Sanitización de Datos** | Prevención de inyecciones SQL y XSS |
